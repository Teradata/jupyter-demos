# Reporting Standards — Consistency Reference

Version: 1.0.0
Maintained by: daily-report-pipeline skill
Applies to: all reports generated by the daily-report-pipeline workflow

---

## 1. Color Palette

| Role | Hex | Use for |
|---|---|---|
| Primary | `#4F8EF7` | Main data series, default bars/lines |
| Success / Positive | `#34C98B` | Growth, on-target, healthy metrics |
| Warning | `#F7934F` | Near-threshold, caution |
| Negative / Alert | `#E05C5C` | Decline, off-target, critical |
| Accent | `#A78BFA` | Secondary series, highlights |
| Neutral | `#94A3B8` | Baselines, prior period, background |

Do NOT introduce colors outside this palette without updating this document.

---

## 2. Chart Type Rules

| Use case | Chart type | Notes |
|---|---|---|
| Trend over time | `line` or `area` | Area when cumulative; line when point-in-time |
| Comparison across categories | `bar` | Horizontal bar if >6 categories |
| Parts of a whole | `doughnut` | Max 6 slices; group remainder as "Other" |
| Distribution / histogram | `bar` | Bin server-side in SQL |
| Two metrics over time | `line` with 2 datasets | Use primary + accent colors |
| Correlation | `scatter` | Only when sample >100 rows |
| Single KPI | `stat-card` | Never use a gauge — use stat-card with color |

---

## 3. Report Structure (every report must have)

1. **Header** — Report name, description, date badge
2. **Stat Cards** — Top 3-5 headline KPIs with color-coded trend direction
3. **Primary Chart** — The main story chart (trend or comparison)
4. **Supporting Charts** — 0-2 additional charts for context
5. **Data Table** — Top N rows (max 20) of underlying data
6. **Footer / Key-Value block** — Data source, last refreshed timestamp, skill version

---

## 4. Tone & Copy Rules

- **Lead with the insight**, not the data. Title charts with the takeaway (e.g. "Revenue up 12% MoM" not "Revenue by Month").
- Keep chart titles under 60 characters.
- Audience-aware defaults:
  - `executive` → stat cards first, minimal tables, insight-led titles
  - `analyst` → tables prominent, raw numbers visible, more charts
  - `ops` → alert colors prominent, threshold lines on charts

---

## 5. Artifact Naming Convention

```
report-<report_name>-YYYY-MM-DD
```

Examples:
- `report-sales-daily-2026-11-03`
- `report-ops-kpi-2026-11-03`

---

## 6. Refresh & Versioning

- Reports refresh **daily** at the scheduled executor run time.
- Each daily run saves a **new artifact** (don't overwrite previous days).
- The UI app dashboard is **updated in place** (same app name, fresh data).
- If the underlying skill is updated (new SQL, new metrics), the next daily run automatically picks up the change — no manual trigger needed.

---

## 7. Anomaly Alerting

The daily executor checks for anomalies before saving:
- Any metric that moved **>20%** vs the prior day → log a warning in the artifact footer
- Any metric that moved **>50%** → add a `badges` component with color `warning` to the dashboard
- Null / zero counts where previous day had data → flag as data pipeline issue

---

## 8. Adding a New Report

1. User triggers the `daily-report-pipeline` skill.
2. Skill bootstraps agents (idempotent — won't duplicate).
3. Requirements interview → custom skill authored → first report generated.
4. Daily executor picks up the new skill on next scheduled run.

Do NOT create ad-hoc reports outside this pipeline — all reports must have a corresponding skill in the org repo so they are versioned and reproducible.
